## 已观察到的结果

- 用户在学校 Ubuntu 完成交叉编译并烧录 v2.3.1；LCD 正立预览、人脸框和 FACE_STABLE 已确认。
- 串口节奏调整后，用户报告无人运行 15 分钟、进出镜头 10 次、连续面对镜头 5 分钟均未冻结或离线。这是有限实板观察，未证明长期故障消除。
- 板端输入已出现身份匹配、权限允许、ACK ALLOW|OK，随后 STATE LOCKED 的成功记录；另有允许后被取消和执行错误的记录。

## 待解决问题

一次已核对的请求在特征接收后发出 ALLOW，随后收到 FCANCEL FACE_CHANGED 和 ERR STALE_REQUEST。该次并非 8 秒总期限到期；具体是无脸、多脸、质量还是特征漂移触发仍不确定。不要将问题直接归因于人员移动。后端收到取消后没有充分唤醒等待中的决定命令，可能继续等到超时。该问题本次保持现状，未放宽板端保护，也未重发过期允许。

LCD 曾在热复位后黑屏、完全断电后恢复，根因未定位。多来源录入跨摄像头效果、C/OpenCV 同 ROI 特征一致性、准确率及完整异常场景仍待评估。后续安排见 待联调事项.md。

## 交付范围与复现

本分支包含前后端源码、依赖清单及锁文件、板端应用/接入脚本、技术与实板记录。人员数据库、照片、特征、校准阈值、日志、学校文档、模型、固件二进制和工具安装程序均不提供。原仓库历史中的文件未改写；这里只清理新分支最新目录。

先按根 README 安装依赖和构建前端，创建本机数据，再登记、校准。学校 XiZi 完整工程和交叉工具链需要另行取得。backend/tests 中仅保留原有源码脚本，原测试图片、数据库和输出已排除；这些脚本不作为本次功能验收证据。本次整理不运行测试，不操作串口、后端进程或开发板。

历史增量诊断安装器保留供追溯，首次接入使用 firmware/edu-riscv64/README.md 的完整安装步骤。旧 tools/package_sources.py 未纳入本分支：其从当前源码覆盖旧版本 ZIP 的行为不适合本次交付。
