# 特征协议和算法改动

2026-10-15。算法 lbph4-v1 绑定预处理 gray160-nn-eq-v1；修改尺寸、灰度、均衡、ELBP、网格或字节序必须换版本并重新录入/校准。

学校 face.kmodel 只检测人脸框，不判断人员身份。板端从 320×240 平面 RGB 取单脸 ROI，用 (77R+150G+29B)>>8 灰度、整数最近邻缩放为 160×160、代码中的整数均衡，然后圆形 ELBP（radius1、neighbors8、双线性插值）。158×158 有效区域以 4×4 个 39×39 网格取直方图，末尾两行/列弃去，格内归一化。4096 个 little-endian float32，即 16384 字节。C/OpenCV 同 ROI 数值一致性仍需现场对照，编译通过不证明一致。

后端 HISTCMP_CHISQR_ALT 距离越小越相似，不是概率。原 8×8 特征为 65536 字节，4×4 减少传输，但准确率需独立比较。115200、8N1 下 16384 字节纯二进制理论下限约 1.42 秒，Base64 数据约 21848 字节、约 1.90 秒，还加帧头/处理耗时；不是实际耗时/FPS。

2026-10-15 增加照片/Windows 摄像头录入：POST /api/edge/image-sample 用 Haar 检测单脸，再按相同整数灰度、160×160 最近邻、整数均衡化和 OpenCV 4×4 LBPH 生成模板。与板端样本共用 edge_samples，记录 board/upload/webcam 来源及图片内容摘要，避免原图重复登记；不写入旧 face_samples。图像来源差异及 Haar/KPU 裁剪差异需用板端独立验证评估，C/OpenCV 数值一致性仍待现场对照。操作见 多来源人脸录入使用说明.md。

新增 edge_samples/edge_thresholds，旧照片表保留且不混用。每人至少 3 训练与 3 独立验证，并有其他身份/陌生人负例；禁止完全相同特征跨训练/验证复用。求该人验证对训练模板最小距离的最大值 own_max、负例对该人模板最小距离的最小值 cross_min。差值大于候选间隔 5 才取中点阈值，否则未校准。现场最佳身份满足阈值，且与第二个不同身份相差至少 5，才确认身份。参数是待评估候选值，不是有统计保证的生产阈值。

停用人员仍保留为身份候选，授权时拒绝，避免错误改判为别人。匹配后检查 enabled、本门权限、有效期，发送前再次查询；样本变动使阈值失效。旧 face_service 修复损坏图过滤后的标签错位、模型替换读取竞态及交叉距离方向，旧模型/阈值仅用于兼容对照。

## 串口

RX 由 letter-shell 单独读取，后端只有一个读线程，匹配/数据库工作独立排队。

```text
Windows -> FaceProbe <12hex>
Board   -> AC|FPROBE|<12hex>|<session/NONE>|<running0/1>|<state>
Windows -> FaceHello <new-session>
Board   -> AC|FREADY|<session>|lbph4-v1
Board   -> AC|FBEGIN|<request>|<session>|lbph4-v1|16384|<crc8hex>|INFER/ENROLL
Board   -> AC|FCHUNK|<request>|<byte-offset>|<base64-512bytes>
Board   -> AC|FEND|<request>|<session>
Board   -> AC|FCANCEL|<request>|<reason>
Windows -> FaceEnroll <request>
Board   -> AC|FENROLL|<request>|OK
Windows -> FaceSaved <request>
Board   -> AC|FSAVED|<request>|OK
Windows -> FaceDecision <current-request> ALLOW/DENY
Board   -> AC|ACK|<request>|ALLOW/DENY|OK
Board   -> AC|STATE|<request>|LOCKED
```

ID 为 12 位小写 hex，避免 ffff 前缀。推理 ID=随机服务器会话值+板端计数，新会话清除待决请求；用于意外旧回复隔离，不是认证协议。Shell 命令最多 64 字符，接收行最多 1024，分块最多 512 原始字节、按偏移顺序、总长 16384、8 秒内组装、CRC 和格内归一化检查通过才处理。

板端只等待一个请求，创建起 8 秒超时；收到决定先排队，下一张完整/合格现场图与待授权特征接近才提交 GPIO；多人、无脸、质量失败、漂移、停止或超时取消。上传期间不能持续观察，中间离开又回来或相似特征不能严格证明同一人，是原型限制。

五帧稳定不是身份投票或活体能力。一次请求后至少三帧无人重新允许触发，录入不走开锁路径。ACK 表示 GPIO 成功，STATE 表示 LED 恢复，不代表实体门已开。每块单次 printf，后端传输期暂停心跳；内核/Shell 输出仍可能交错，CRC 错则丢弃。需上板测量输出稳定性。重连不重发旧允许指令。
