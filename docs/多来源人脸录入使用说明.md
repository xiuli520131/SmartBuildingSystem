# 上传照片与 Windows 摄像头录入

更新：2026-10-15。代码位于 D:\SmartBuildingSystem\smart-access-demo。本次只更新 Windows 前后端，使用现有 v2.3.1 固件即可。

## 启用新版页面

1. 正在运行后端时，在原 PowerShell 窗口按 Ctrl+C。
2. 如果要接入开发板，先关闭 MobaXterm、K-Flash 的串口会话，将 USB 留给 Windows。当前实际端口为 COM10，重新插拔后需重新确认。
3. 在原已配置环境变量的 PowerShell 窗口执行：

```powershell
cd D:\SmartBuildingSystem\smart-access-demo\backend
& ..\.venv\Scripts\python.exe -m app.main
```

新开 PowerShell 时，按 Windows板端联调步骤.md 第 3 节完整设置 board/serial/COM10/demo-data 等环境变量后启动，避免使用了默认数据目录或模拟模式。

4. 浏览器打开 http://127.0.0.1:8000，按 Ctrl+F5 强制刷新，进入“人员与权限”，点击某个人员的“采集人脸”。

前端 dist 已重新构建，无需另启动 npm 开发服务。重启后自动增加样本来源字段，原人员、权限和既有特征保留。

## 三种样本来源

| 来源 | 操作 | 是否需要板子在线 |
| --- | --- | --- |
| 上传照片 | 选择照片，查看预览，点击保存 | 否 |
| Windows 摄像头 | 打开摄像头，允许浏览器权限，点击“拍摄并保存” | 否 |
| 板载摄像头 | 面对板载相机，点击“采集板载特征”并等待保存 | 是 |

上传支持 JPEG、PNG、WebP，单张不超过 10 MB，一批不超过 20 张。浏览器先将长边缩小至最多 1280 像素，再提交给后端。每张照片分别显示待保存、处理中、已保存或未保存及原因；已经保存的照片不会因再次点击而重复提交。换照片时重新选择文件。

Windows 摄像头由浏览器打开，可选择已发现的摄像头。仅在点击保存时提交一帧。切换到其他来源、关闭弹窗或离开页面会停止该摄像头。摄像头授权失败时按页面提示恢复；使用本机 127.0.0.1 / localhost 地址。

后端检查照片是否恰好有一张正脸，拒绝无脸、多人、人脸过小、曝光不合格或细节不足的图片。后端只保存特征、来源和照片内容摘要，不另保存上传原图。相同特征或解码后内容相同的照片不能重复登记，也不能改标为独立验证。

## 样本用途与校准

三种来源均可在板端模式下选择训练模板、独立验证、陌生人验证。陌生人验证不绑定当前所选人员，必须由实际未登记人员入镜。

每人至少 3 份训练特征和 3 份新采集的独立验证特征，另需他人或陌生人负例。不要把同一次拍摄的照片在训练与验证之间复制。上传照片/电脑摄像头用于便利录入后，建议用实际门口的板载摄像头采集独立验证，用于判断跨摄像头效果。

新增任何来源的样本都会使全部板端特征阈值失效。采集完成后关闭弹窗，点击“阈值校准”。本人/他人距离没有足够间隔时保持未校准，应检查样本和现场成像，而不是直接放宽阈值。校准后仍需独立现场评估。

## 算法与边界

新增 POST /api/edge/image-sample，参数为 user_id、role、source（upload/webcam）、image（base64）。后端独立于串口进行检测与特征计算，调用现有 FeatureService 写入 edge_samples。

图片检测使用现有 OpenCV Haar 正脸检测器，特征预处理按固件的 (77R+150G+29B)>>8 灰度、最近邻 160×160 和整数均衡化，LBPH 仍为半径 1、8 邻点、4×4 网格、4096 个 float32，版本 lbph4-v1 / gray160-nn-eq-v1。没有调用旧照片模型的默认 8×8 特征作为板端模板。

相同参数格式不等于已证明跨摄像头准确率。Haar 与 KPU 的检测框、摄像头画质和光线可能造成匹配距离变化；同一 ROI 的 C/OpenCV 特征数值对照仍待完成。本次完成 Python AST、后端模块导入和 TypeScript/Vite 构建检查，未新增/运行自动化测试，尚未做真实上传、Windows 摄像头采集及板端匹配的现场验收。

## 本轮离线现象

网页曾记录 COM10、COM9 通信不可用；本机实际枚举为 COM10。旧 API 没有暴露桥接已有的 last_error 字段，新版“设备状态”增加“串口诊断”，可看到打开失败、无 PONG、读取中断或心跳超时等信息。离线时摄像头文字标为“最近上报状态”，避免将历史 NO_FACE 当作实时状态。

用户复位日志正常：camera/KPU initialized，ready=1、running=0、STOPPED、error=NONE。此时预览未启动，黑屏不代表系统异常。手动 Face start 后最新反馈为 frames=155、FACE_STABLE、feature=142ms、error=NONE；Door ping 返回 PONG，utask01 栈约 14%。证明这一轮恢复采图和 Shell 响应，不能据此宣布此前冻结/离线根因已解决。

如果再次冻结，在后端退出、MobaXterm 独占串口时保留 Face、Door ping、ShowTask 或 Exception 输出；后端运行期间不要同时打开串口终端。
